# Spice Python SDK v4.0.0

The v4.0.0 release introduces a lazy DataFrame API and expression DSL, adds search, runtime status, active-query management, and mTLS support, modernizes the runtime requirements, and bumps core dependencies to their latest major versions.

## Upgrading from 3.x

**Spice.ai Cloud: pass both `flight_url` and `http_url`, using your app's region** (e.g. `us-east-1`, `us-west-2`, `eu-west-1`). The legacy hostnames are retired, and `Client()` without URLs now targets a local runtime:

```python
client = Client(
    api_key="API_KEY",
    flight_url="grpc+tls://us-east-1-prod-aws-flight.spiceai.io",
    http_url="https://us-east-1-prod-aws-data.spiceai.io",
)
```

**Runtime requirements:** Python 3.11+ (3.9/3.10 dropped). Dependency floors moved to current majors — upgrade pandas to 3.x and pyarrow to 25+ in your environment before (or together with) spicepy.

Everything else is additive: existing `query()`, `query_with_params()`, and `refresh_dataset()` code runs unchanged.

## Fixed

A new live-runtime integration suite (`tests/test_integration_local.py`, #190) caught four real `SpiceDataFrame`/`Expr` bugs that unit tests mocking the runtime couldn't:

* `DataFrame.drop()`, `.rename()`, `.cast()`, and `.unnest()` never worked against the real runtime — they compiled to `* EXCLUDE (...)` / `* REPLACE (...)` star modifiers the runtime's SQL parser rejects outright. They now resolve the frame's column list with a zero-row query and rewrite the projection explicitly.
* `DataFrame.sort().limit()` silently returned unordered rows — `limit()` wrapped the sorted frame in a subquery, and the planner is free to discard a subquery's ordering. `LIMIT` now shares the `ORDER BY`'s query level.
* `Expr.over(order_by=col(x))` (a bare column/expression, not a list) hung forever — `Expr` supports `__getitem__` for array indexing, so iterating a bare `Expr` yields index expressions endlessly. Scalar `partition_by`/`order_by` are now boxed into a list.

If you use any of these operations, upgrade — no code changes needed, they just work correctly now.
