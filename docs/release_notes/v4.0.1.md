# Spice Python SDK v4.0.1

v4.0.1 is a bug-fix release on top of v4.0.0. It changes how API keys reach a self-managed Spice runtime, binds numpy and pandas scalars as query parameters, and reports the runtime's own error message from HTTP calls.

```bash
pip install git+https://github.com/spiceai/spicepy@v4.0.1
```

## Fixes

### API keys on self-managed runtimes

When you send the key to a self-managed Spice runtime (an address outside Spice Cloud), or when the key does not use the `<appId>|<secret>` format, the key now goes out as `Authorization: Bearer <key>` on Flight calls and on ADBC calls (`sql_with_params()` and `params=`). Before, the ADBC path always used a Basic handshake, which some self-managed Spice runtime builds with `runtime.auth.api-key` reject with `Invalid handshake request`. A Spice Cloud key (`<appId>|<secret>`) sent to a `*.spiceai.io` host keeps the Basic handshake, as before. HTTP calls still send `X-API-Key`. ([#211](https://github.com/spiceai/spicepy/pull/211))

The same change fixes three related problems:

- A per-call `timeout` applies to that call only. Before, `sql(..., timeout=1)` was kept for every later query on the same client.
- Re-authentication keeps a custom `user_agent`.
- Flight queries without parameters fall back to the `SPICE_API_KEY` environment variable, as the ADBC and HTTP paths already did.

### numpy and pandas scalars as query parameters

Values read back out of a DataFrame now bind as parameters. Before, they raised errors such as `TypeError: Unsupported parameter type: int64`. ([#206](https://github.com/spiceai/spicepy/pull/206))

- numpy integers, floats, and `numpy.bool_` keep their width: `numpy.int32` binds as `int32`, not a widened type.
- `numpy.datetime64` and `numpy.timedelta64` bind as a date, timestamp, or duration in the nearest unit Arrow supports. For example, `datetime64[D]` becomes `date32` and minutes become seconds. Units finer than a nanosecond truncate to nanoseconds.
- `pandas.Timestamp` and `pandas.Timedelta` keep their own unit, so a nanosecond value is no longer truncated to microseconds. A timezone-aware `Timestamp` binds as its UTC instant.
- `NaT` binds as a null of the type its unit would get.
- Month and year `timedelta64` values have no fixed length, so they are refused with a `TypeError`.

```python
import numpy as np

reader = client.sql_with_params("SELECT name FROM items WHERE id = $1", [np.int64(1)])
```

### The runtime's error message on HTTP calls

`refresh_dataset()` and `runtime_status()` raise `SpiceAIError` carrying the runtime's explanation, for example `Dataset no_such_dataset not found`. Before, they raised `requests.HTTPError` with only the status line. `search()` and `nsql()` errors report the runtime's message rather than its raw JSON envelope. ([#197](https://github.com/spiceai/spicepy/pull/197))

### Malformed search responses

`search()` raises `SpiceAIError` when a `/v1/search` response lacks a field the runtime always sends. Before, a body such as `{}` or a proxy's error came back as an empty result. ([#205](https://github.com/spiceai/spicepy/pull/205))

## Upgrade notes

- Code that catches `requests.HTTPError` around `refresh_dataset()` or `runtime_status()` should catch `spicepy.error.SpiceAIError` instead.

## Documentation

- The `search()` docs now describe `keywords` as a prefilter: each keyword is a case-insensitive substring match that rows must contain, not a hybrid ranking signal. ([#208](https://github.com/spiceai/spicepy/pull/208))
